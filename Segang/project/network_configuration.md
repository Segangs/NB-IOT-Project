# ❄️ 우분투 서버 네트워크 최적화 및 트러블슈팅 보고서

본 문서는 PicoTeam 관제 웹 대시보드 서버 구동 중 발생한 네트워크 이슈(접속 거부, 로딩 지연, 공인 IP 변동)의 원인을 진단하고 이를 해결하기 위해 적용한 네트워크 아키텍처 및 설정 내역을 상세히 기록합니다.

---

## 1. 개요 및 네트워크 환경 정보

현재 우분투 서버는 아래와 같이 **듀얼 네트워크 인터페이스(유선/무선)**를 동시에 탑재한 환경에서 동작하고 있습니다.

* **유선 랜카드 (`enp3s0`)**: 공유기의 **Twin IP (Super DMZ)** 설정을 통해 공인 IP **`221.158.174.164`**를 DHCP로 직접 할당받아 외부 통신 및 대시보드 서빙용으로 사용합니다.
* **무선 랜카드 (`wlp2s0`)**: 공유기 내부 Wi-Fi망에 접속되어 사설 IP **`192.168.0.229`**를 할당받아 로컬 네트워크 통신용으로 사용합니다.
* **사용 도메인**: `segang.duckdns.org` (보안 SSL인증서가 적용된 웹 주소)

## 2. 진단된 핵심 이슈 및 해결 방안

### 🚨 이슈 1: 공인 IP 불일치로 인한 접속 거부 (ERR_CONNECTION_REFUSED)
* **원인**: 
  - SSL 인증서(Certbot) 수동 발급 및 갱신 API 호출 시, DuckDNS 서버에 IP를 명시하지 않고 텍스트 레코드만 갱신하는 쿼리를 요청하면 **DuckDNS가 요청한 공유기의 외부 WAN IP(220.83.217.105)로 도메인 A 레코드를 임의 갱신**해 버리는 부작용이 있었습니다.
  - 이로 인해 도메인이 엉뚱한 IP를 지목하게 되어 외부 접속이 차단되었습니다.
* **해결 방안**:
  - `main.py` 내부에 **DuckDNS 자동 IP 갱신 데몬 스레드**를 구축했습니다.
  - Flask 웹서버가 켜질 때와 구동 중 매 10분 주기로 현재 서버 유선 랜카드(`enp3s0`)의 실시간 공인 IP를 조회하여 DuckDNS에 명시적으로 전송 및 갱신합니다.

### 🚨 이슈 2: 메뉴 이동 시 간헐적인 접속 끊김 및 렉 현상 (비대칭 라우팅)
* **원인**:
  - 맥북(`192.168.0.251`)이 유선 공인 IP(`221.158.174.164`)로 대시보드 데이터를 요청하면, 패킷은 유선 인터페이스(`enp3s0`)로 진입합니다.
  - 하지만 응답할 때, 맥북 IP가 로컬 대역(`192.168.0.x`)이므로 우분투 커널은 더 가까운 경로로 매핑된 무선 인터페이스(`wlp2s0`, 192.168.0.229)를 통해 응답을 보냅니다.
  - **들어올 때는 유선, 나갈 때는 무선**으로 패킷이 엇갈리는 **비대칭 라우팅(Asymmetric Routing)**이 발생하여, 공유기 방화벽 및 맥북 네트워크 단에서 보안 상의 이유(IP Spoofing 의심)로 패킷이 무작위 드랍되었습니다.
* **시도했던 방안 (사설 IP 추가 및 한계)**:
  - 유선 랜에 가상의 사설 IP `192.168.0.200`을 임시 추가하려 했으나, 공유기 Twin IP 기술의 특성상 해당 유선 포트가 로컬 LAN 대역과 격리되어 있어 `192.168.0.200` 대역의 브로드캐스트 패킷이 차단되었습니다.
* **최종 해결 방안**:
  - 무선을 끄지 않고 유선 연결을 살리기 위해, **소스 IP 기준 정책 라우팅(Source-Based Policy Routing)**을 구축했습니다.
  - **"소스 IP가 유선 공인 IP인 모든 응답 패킷은 기본 라우팅 테이블 대신 전용 테이블(table 100)을 사용하여 강제로 유선 게이트웨이(221.158.174.129)로 내보낸다"**는 커널 룰을 적용했습니다.
  - 결과적으로 들어왔던 유선 포트로 응답이 대칭적으로 나가면서 렉과 끊김 현상이 완벽히 해소되었습니다.

## 3. 유동 IP 환경 대응 자동화 및 스크립트 상세 설명

유동 IP 환경에서는 통신사 DHCP 임대 기간이 만료되거나 서버 장비 재시작으로 공인 IP 주소가 수시로 바뀔 수 있습니다. 

고정된 특정 IP 주소를 기반으로 정책 라우팅(`ip rule`)을 등록해 두면 IP가 바뀌는 순간 규칙이 깨집니다. 이를 해결하기 위해 **이벤트 트리거 기반의 자동 갱신 아키텍처**를 구축하였습니다.

### 1) 자동화 아키텍처 구성 및 도구 선정
* **적용 도구**: `networkd-dispatcher` (우분투 서버 기본 내장 네트워크 디스패처)
* **작동 원리**: systemd-networkd 서비스가 랜선의 연결이나 DHCP 임대 갱신 등으로 인터페이스의 상태 정보를 감지하면, `networkd-dispatcher`가 관련 상태 디렉토리에 위치한 실행 스크립트들을 **Root(root) 관리자 권한으로 자동 실행**합니다.
* **선정 디렉토리**: `/etc/networkd-dispatcher/routable.d/`
  - 이 디렉토리 하위 스크립트들은 인터페이스가 IP 주소를 온전히 받아 **인터넷 연결(라우팅)이 가능한 상태(routable)**가 되었을 때 트리거됩니다.

---

### 2) 자동화 스크립트 단계별 분석 및 상세 설명
위치: `/etc/networkd-dispatcher/routable.d/50-enp3s0-policy-routing`

스크립트는 **[필터링] ➡️ [정보 추출] ➡️ [기존 캐시 제거] ➡️ [신규 정책 수립]**의 4개 절차를 거치며 작동합니다.

#### [Step 1] 대상 인터페이스 필터링 (라인 3-6)
`networkd-dispatcher`는 가상 브릿지(docker)나 루프백(`lo`), Wi-Fi(`wlp2s0`) 등 모든 네트워크 상태 변경 시 작동하므로, 유선 공인 IP 변경 시에만 이 스크립트가 실행되도록 차단벽을 세웁니다.
```bash
if [ "$IFACE" != "enp3s0" ]; then
    exit 0
fi
```
* `$IFACE`: `networkd-dispatcher`가 실행할 때 환경 변수로 전달해 주는 인터페이스명입니다. 유선 랜카드인 `enp3s0`일 때만 스크립트 로직을 속행합니다.

#### [Step 2] 실시간 동적 공인 IP 추출 (라인 8-21)
유선 랜카드(`enp3s0`)에 임시 사설 IP(`192.168.0.200`) 등이 섞여 있더라도, 통신사가 할당해 준 **진짜 유동 공인 IP**만 필터링하여 찾아냅니다.
```bash
IP_ADDR=""
while read -r line; do
    if [[ "$line" =~ "dynamic" ]]; then
        if [[ "$line" =~ inet\ ([0-9.]+) ]]; then
            IP_ADDR="${BASH_REMATCH[1]}"
        fi
    fi
done < <(ip -4 addr show enp3s0)
```
* **작동 상세**:
  - `ip -4 addr show enp3s0` 명령어 출력 중, DHCP로 공급받는 유동 공인 IP 줄에는 항상 `dynamic`이라는 텍스트가 명시됩니다.
  - 루프를 돌며 `dynamic`이 포함된 줄을 걸러낸 뒤 정규표현식(`inet [IP주소]/대역`)을 사용해 정확한 IP 주소 문자열만 골라냅니다.
* **예외 처리 (Fallback)**:
  - 시스템 상황에 따라 일시적으로 `dynamic` 키워드가 조회되지 않는 비상 상황을 대비해, `enp3s0`에 설정된 첫 번째 IPv4 주소를 가져오도록 Fallback 조건문을 추가했습니다.
  ```bash
  if [ -z "$IP_ADDR" ]; then
      IP_ADDR=$(ip -4 addr show enp3s0 | grep -oP '(?<=inet\s)\d+(\.\d+){3}' | head -n 1)
  fi
  ```

#### [Step 3] 유선 게이트웨이(Gateway) 주소 추출 (라인 23-24)
외부 인터넷으로 응답 패킷을 토스해 줄 공유기의 유선 WAN측 게이트웨이 주소(예: `221.158.174.129`)를 파악합니다.
```bash
GW_ADDR=$(ip route show dev enp3s0 | grep default | awk '{print $3}' | head -n 1)
```
* `ip route show dev enp3s0`: 유선 랜카드 관련 경로만 필터링하여 조회합니다.
* `grep default | awk '{print $3}'`: `default via [GW_IP] dev enp3s0` 형태의 행에서 세 번째 열의 값인 게이트웨이 IP(`[GW_IP]`)를 뽑아냅니다.

#### [Step 4] 기존 규칙 및 경로 비우기 (라인 27-33)
IP가 변경되었을 가능성이 있으므로, 기존에 커널이 보관하고 있던 구버전 IP 룰과 라우팅 테이블 100의 이력을 완전히 클리어합니다.
```bash
ip route flush table 100 2>/dev/null
while ip rule del table 100 2>/dev/null; do
    true
done
```
* `ip route flush table 100 2>/dev/null`: 테이블 100의 이전 라우팅 캐시를 제거합니다. 최초 실행 등으로 해당 테이블이 없어 오류를 반환하더라도 무시하도록 `2>/dev/null` 처리를 추가했습니다.
* `while ip rule del...`: 이전에 맵핑해 둔 구버전 IP rule들을 모두 찾아서 지워질 때까지 반복하여 완벽히 말소합니다.

#### [Step 5] 신규 정책 라우팅 선언 및 적용 (라인 35-37)
추출한 실시간 공인 IP와 유선 게이트웨이 정보를 조합하여 최신의 대칭형 라우팅 커널 규칙을 선언합니다.
```bash
ip rule add from "$IP_ADDR" table 100
ip route add default via "$GW_ADDR" dev enp3s0 table 100
```
* `ip rule add from "$IP_ADDR" table 100`: "송신 출발지(Source) IP가 현재 갱신된 공인 IP(`$IP_ADDR`)인 패킷은 무조건 라우팅 테이블 100번을 보고 길을 찾으라"고 선언합니다.
* `ip route add default...`: "테이블 100번을 따르는 패킷은 무조건 유선 랜포트(`enp3s0`)를 사용해 유선 게이트웨이(`$GW_ADDR`)로만 내보내라"고 강제 규정합니다.

#### [Step 6] 동작 로그 저장 (라인 39)
성공적으로 갱신이 일어나면 변경 일시 및 IP 정보를 파일로 남겨 사후 진단이 쉽도록 조치합니다.
```bash
echo "[$(date)] Configured policy routing for enp3s0: IP $IP_ADDR via GW $GW_ADDR" >> /var/log/policy-routing.log
```

## 4. 최종 라우팅 구조 및 검증 내역

스크립트 실행 완료 후 커널에 활성화된 실제 라우팅 상태는 다음과 같습니다.

### 1) 정책 규칙 (`ip rule`)
```bash
$ ip rule
0:	from all lookup local
32765:	from 221.158.174.164 lookup 100   # 유선 공인 IP로 나가는 패킷은 table 100 참조
32766:	from all lookup main             # 그 외(Wi-Fi, 로컬망) 패킷은 메인 테이블 참조
32767:	from all lookup default
```

### 2) 전용 테이블 경로 (`ip route show table 100`)
```bash
$ ip route show table 100
default via 221.158.174.129 dev enp3s0    # 오로지 유선 포트를 통해 유선 게이트웨이로만 전송
```

### 3) 메인 테이블 경로 (`ip route show`)
```bash
$ ip route
default via 221.158.174.129 dev enp3s0 proto dhcp src 221.158.174.164 metric 100 
default via 192.168.0.1 dev wlp2s0 proto dhcp src 192.168.0.229 metric 600 
192.168.0.0/24 dev wlp2s0 proto kernel scope link src 192.168.0.229 metric 600 # 로컬 통신은 Wi-Fi를 우선하여 mDNS(segang.local) 안정 유지
```
